# Project Documentation

Use this directory for durable project documentation. Create only the documents
the project needs, then record their authoritative paths in
`.agents/project-context.md`.

Recommended areas:

- `architecture/`: system boundaries, data flows, and ownership.
- `design/`: visual direction, accessibility, and UI conventions.
- `database/`: schema, retention, and migration guidance.
- `setup/`: local development, environments, and operational runbooks.
- `adr/`: accepted architecture decisions.

Keep documentation factual and synchronized with implemented behavior.
